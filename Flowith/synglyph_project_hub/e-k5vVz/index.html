System Architecture

1. Overview: The Vision for SYNLGLYPH

The SYNLGLYPH project is an initiative to engineer an advanced AI system for semantic and symbolic modeling. The system's primary goal is to process unstructured data (primarily text) and transform it into a rich, structured `Concept` model. This model will capture not just explicit information but also latent relationships, conceptual weight, and contextual resonance.

2. Architectural Foundation: A Microservices Approach

A microservices architecture is selected as the foundational pattern. This allows for technological flexibility, independent scalability, resilience, and maintainability—critical for complex, evolving AI systems.

3. Core Component Breakdown

  • Semantic Modeling Service (`Nous`): The intellectual core, responsible for text analysis, RAG, and constructing the `Concept` model.
  • Glyph_Bus: An asynchronous communication backbone using Apache Kafka for reliable, scalable data flow.
  • Selene: A dedicated integration and validation suite for ensuring system integrity using contract, pipeline, and behavioral testing with `Testcontainers`.
  • API Gateway: The single, managed entry point for all external interactions, handling routing, authentication, and rate limiting.
Message Broker: RabbitMQ vs. Apache Kafka
Feature RabbitMQ Apache Kafka
Primary Model Smart Broker / Dumb Consumer Dumb Broker / Smart Consumer
Paradigm Message Broker (complex routing) Distributed Event Log (streaming)
Data Retention Messages are deleted after consumption. Messages persist based on a retention policy.
Key Use Case Reliable task queues, complex routing logic. Real-time data pipelines, event sourcing, data replay.

Recommendation: Apache Kafka. Its persistent log enables data replayability for testing and retraining models, a crucial feature for AI development.

4. Data and Message Flow: A Typical Use Case

  1. Client sends `POST` request to the API Gateway.
  2. Gateway authenticates and routes to `Nous` service.
  3. `Nous` publishes a job to the `documents.pending` Kafka topic.
  4. A `Nous` consumer instance processes the job.
  5. `Nous` publishes the resulting `Concept` object to the `concepts.completed` topic.
  6. Client receives the result via asynchronous response or WebSocket.
